# Which modules to load

Always load `core/`. Then add only what the task needs. Loading everything wastes attention. Each module's `notes.md` is optional depth; open it only when a critique needs it. Open `core/evidence.md` before claiming that people prefer something.

| Task | Load |
|---|---|
| Drawing or painting from imagination, concept art, scene | technical-drawing, illustration |
| Any human or humanoid figure, face, hand or animal (drawn, 3D or generated), even small or partial | character (anatomy pass CHAR-9 required), technical-drawing (+ illustration) |
| Checking a drawing for construction errors only | technical-drawing |
| Poster, cover, header image, social graphic, thumbnail, link preview | layout, typography (+ illustration for the image; brand if it carries a name) |
| Slide deck, print piece (flyer, book cover, packaging) | layout, typography (+ brand) |
| Anything with words where type is the point (wordmark, editorial page, type-led poster) | typography (+ layout or web-ui) |
| Work for a named brand or product, or with a brand guide | brand (+ the medium's module). No brand input at all: run `core/brand-intake.md` at step 0 |
| Web page, landing page, app screen, dashboard (how it looks) | web-ui (+ typography for text-heavy pages; brand when there's a brand) |
| Sign-up, checkout, settings, any multi-step task (how it works) | ux (+ web-ui for the screens) |
| Reviewing a whole product or prototype | web-ui, ux |
| 3D model, prop, asset, scene for render, game or print | 3d (+ illustration for a final beauty render or composed shot) |
| 3D used as reference for a drawing or painting | 3d, technical-drawing |
| Logo, icon set | illustration (shape, value), web-ui (size and contrast rules) |
| Storyboard, comic page, carousel or any image sequence | illustration (ILL-7 for intensity across frames; `notes.md` for panel transitions) |
| Brief asks for a mood, energy, character or a distinctive feel; work that is correct but flat or generic; choosing between versions | aesthetic-critique (+ the medium's modules, which still decide blockers) |
| Remake from scratch ("redo", "rejig", "start over", "reimagine") | `core/first-principles.md` (FP-1..8) + the medium's modules + aesthetic-critique (AES-9 for comparing with the original); brand if the piece carries any logo or mark |
| Image generated by an AI image model | illustration, technical-drawing (AI images often break perspective and light); brand for any logo-bearing surface (BRAND-8); + character if it shows people, hands or animals (anatomy pass CHAR-9 is a delivery gate) |

## Quick questions if unsure

1. Is it a picture people *look at*? -> illustration.
2. Does it depict 3D space, objects or bodies? -> technical-drawing.
3. Is it a screen people *use*? -> web-ui, and ux if they have to get something done.
4. Is it a 3D file? -> 3d.
5. Does it show a person, a hand or an animal? -> character, and run the anatomy pass (CHAR-9) before hand-off.
6. Is it a fixed frame (social post, thumbnail, poster, slide, print)? -> layout. Does it carry words? -> typography.
7. Does it carry a name or logo? -> brand. No brand input in the brief? -> `core/brand-intake.md` first.
8. Is it correct but flat, or are you choosing between versions? -> aesthetic-critique.
9. Did the owner ask for it from scratch, a redo or a rejig? -> `core/first-principles.md` before anything else. Any logo, crest or sponsor mark in it, or generated imagery with jerseys, bottles or signs? -> brand (BRAND-4, BRAND-8).

## Order of checks when several modules apply

1. Core hierarchy and value (does it read at all?)
2. Technical errors (perspective, proportion, anatomy pass, light, broken flows, failing contrast) - these are ERRORs.
3. Composition and layout.
4. Surface: edges, texture, micro-spacing, polish.
